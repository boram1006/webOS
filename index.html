01 · 보고에 앞서

왜 지금, UX Draft? 자동화 Agent인가

현 webOS UX 디자인 프로세스의 구조적 문제, 외부 도구 대비 자체 개발의 필요성, 그리고 본 보고에 이르기까지의 경과를 정리했습니다.

01 — BACKGROUND

AX 과제 발의 배경

  • 현재 webOS UX 디자인 프로세스는 CP 단계에서의 요구사항 검토 완료 전 시나리오 배포가 필요한 상황으로, 배포 전 양산 GUI 디자인을 충분히 검토할 물리적 시간 확보가 어려운 구조
  • 이로 인해 시나리오 배포 이후에도 디자인 보완과 개발 대응 업무가 병행되며, 특정 시점에 업무 부하가 과도하게 집중되는 ‘크런치 모드’가 반복됨
⇒ 효율적 인적 자원 배분과 고객 중심 UX 구상에 역량을 집중하도록, UX Draft 디자인 자동화 Tool 개발로 업무 리드타임 33% 단축을 추진
02 — TREND

생성형 AI 디자인 트렌드 및 자체 개발 필요성

  • 범용 UI/GUI 생성 AI(Claude 등)는 초기 단순 시각 레이아웃 렌더링에서 벗어나, 기존 화면 구조를 이해하고 디자인 시스템과 연동하여 재사용 가능한 에셋을 생성하는 방향으로 고도화
  • 보안 정책으로 인해 Figma Make(Figma AI)를 포함한 외부 디자인 생성 툴의 사내 도입·활용이 원천적으로 차단된 상황
  • 범용 외부 툴로는 webOS 고유의 디자인 시스템과 사내 UX 가이드라인을 완벽히 이해·반영한 맞춤형 산출물 생성에 근본적 한계 존재
⇒ 외부 툴 도입에 의존하는 대신, 자사 고유의 디자인 시스템 및 사내 UX 가이드라인에 동기화되어 규격화된 산출물을 생성하는 에이전트 개발이 필요
03 — STATUS

경과 및 현황

  • 문제 인식을 바탕으로, 4월 MS디자인연·AX센터의 M단계 워크샵을 통해 UX 업무 워크플로우 전반의 리디자인 방향성을 검토하여 개발에 착수
  • 금일 보고를 통해 분석 결과 · 시스템 구성 · 기대효과 · 추진 일정을 공유드리고자 함
참고 CP기준, 요구사항 검토 보고서와 UI 시나리오 1.0 Release 시점은 동일
02 · 현재 프로세스 분석

UX 업무 프로세스 분석을 통한 리디자인 과정

PRD 리뷰 단계부터 AI Agent를 활용하여 UI/GUI 업무 흐름을 AI 중심으로 재설계합니다. 분석 결과 전체 168개 Activity 중 65개(UI 49 + GUI 16)가 자동화 대상으로 식별되었으며, 이는 약 135.5시간의 효율화로 환산됩니다.

As-Is Process Chain · 단계별 활동과 AX 자동화 대상

현 UX 업무 프로세스를 6단계 × 3트랙(Process Group / UI / GUI)으로 분해. 깜빡이는 셀이 AI Agent로 자동화 가능한 활동입니다. UI 65.75h · GUI 69.7h, 합계 약 135.5h의 효율화가 예상됩니다.

핵심 질문

“분석도 했고 각각의 Activity를 자동화할 에이전트도 구상했어. 그리고 양산 GUI 디자인까지 AI가 빨리 생성해 주면 문제가 해결될까?”

실무진 인터뷰 및 워크샵(M단계)을 심층 진행한 결과, 단순 ‘AI 가속’ 만으로는 풀리지 않는 구조적 문제 3가지를 식별했습니다.

PROBLEM · 01

중간 산출물이 끊긴다

회의 초안, 중간 시안 등 각 단계의 결과물이 후속 공정의 직접적 입력(Input)으로 계승되지 못하고 단순 이미지·문서 형태로 고립됨.

PROBLEM · 02

시나리오와 GUI 컴포넌트 구조 분리 운영

시나리오 단계의 임시·범용 와이어프레임 구조와 GUI 단계의 실제 디자인 시스템(Dark 테마 등) 컴포넌트 간 규격이 상이함.

PROBLEM · 03

데이터 자산화 한계

중요한 내부 자산인 디자인 시스템이 Figma라는 외부 플랫폼 라이브러리에 저장되어 있어, 직접 제어·활용할 수 있는 ‘데이터 자산’으로 구축되지 못함.

03 · 프로세스 전환 방향

순차 제작에서 연계 생성으로

UI 시나리오가 끝난 뒤 GUI를 시작하는 구조에서, PRD 이후 UI와 GUI가 함께 준비되는 구조로 프로세스를 재설계합니다.

04 · 시스템 구성DRAFT · 확인필요

Agent는 사내 디자인 지식을 기반으로 UX 시나리오와 GUI 구조를 생성하고, Figma는 시각화·편집 채널로 활용

Figma는 최종 저장소가 아니라 렌더링/편집 채널이며, 핵심 자산은 AI-readable Design Knowledge와 구조화 Output 데이터입니다.

용어 정리

UX 디자인 프로세스에서 단계별로 만들어지는 산출물의 정의입니다. 뒤로 갈수록 디테일과 충실도(fidelity)가 높아집니다.

STAGE 01

Draft UX/ 드래프트 UX

가장 초기에 기획·디자인·개발이 함께 보며 논의하기 위해 그리는 가벼운 스케치. 화면 단위·정렬·컴포넌트의 정확성보다 주요 기능과 화면 간 이동 흐름을 빠르게 가시화하는 것이 목적입니다. 손그림 수준의 거친 표현이 허용되며, 방향성을 함께 합의하기 위한 출발점 역할을 합니다.

STAGE 02

Wireframe/ 와이어프레임

Draft UX보다 한 단계 정교화된 화면 설계도. 색상·이미지·서체 같은 시각적 디테일은 의도적으로 배제하고, 영역 구분과 컴포넌트의 위치·크기·계층만 라인으로 표현합니다. 시나리오 검토와 개발 협의의 공통 기준이 되며, 이후 양산 GUI 디자인의 골격이 됩니다.

STAGE 03

UX 시나리오/ UX Scenario

확정된 와이어프레임에 사용자 행동·화면 동작·예외 케이스 설명(Description)을 결합한 문서. 통상 좌측에 와이어프레임, 우측에 텍스트 설명이 짝을 이루어 배치되며, 한 페이지 안에서 시각과 논리를 동시에 검토할 수 있습니다. 유관부서 협의와 개발 인계의 기준 문서로 활용됩니다.

STAGE 04

GUI 디자인/ GUI Design (Hi-Fi)

확정된 와이어프레임 위에 디자인 시스템의 컬러·타입·아이콘·이미지·상태(State)를 모두 입혀 양산 가능한 수준으로 완성한 고해상도(High-Fidelity) 디자인. 실제 사용자가 화면에서 보게 될 최종 시각 산출물이며, 개발에 그대로 전달되는 디자인 가이드의 기준이 됩니다.
